🐳 Docker Complete Notes

1. Docker Fundamentals

What is Docker and containerization?

Docker packages an application with its libraries, runtime and config into a container that runs the same everywhere (laptop, server, cloud). Containers share the host Linux kernel and use namespaces (isolation) and cgroups (resource limits).

Virtual Machine vs Container

PointVirtual MachineContainer
OSFull guest OS eachShares host kernel
SizeGBsMBs
StartupMinutesSeconds
IsolationStrong (hypervisor)Process-level

Architecture: Client, Daemon, Engine

  • Docker Client (docker CLI) sends commands via REST API.
  • Docker Daemon (dockerd) builds, runs and manages objects.
  • Docker Engine = daemon + API + CLI (uses containerd and runc underneath).

Images, Containers, Registries

  • Image: read-only template (like a class).
  • Container: running instance of an image (like an object).
  • Registry: image storage, e.g. Docker Hub, GHCR, AWS ECR.

Install on Ubuntu

sudo apt update && sudo apt install -y ca-certificates curl
curl -fsSL https://get.docker.com | sudo sh      # quick install
sudo usermod -aG docker $USER && newgrp docker   # run without sudo
sudo systemctl enable --now docker
docker run hello-world                           # test
Docker Hub = default public registry at hub.docker.com. Official images (nginx, mysql, ubuntu) are trusted and maintained.

2. Docker Basic Commands

docker --version            # client version
docker info                 # system-wide info (storage driver, containers, cgroup)
docker pull nginx:latest    # download image
docker images               # list images
docker run -d --name web -p 8080:80 nginx   # create + start
docker ps                   # running containers
docker ps -a                # all containers (incl. stopped)
docker stop web / start web / restart web
docker exec -it web bash    # shell inside container
docker logs -f web          # follow logs
docker stats                # live CPU/RAM/network
docker inspect web          # full JSON details
docker rm -f web            # remove container (-f forces)
docker rmi nginx            # remove image
Use docker inspect -f '{{.NetworkSettings.IPAddress}}' web to extract one field.

3. Docker Images

Layers and architecture

An image is a stack of read-only layers; each Dockerfile instruction creates one. Layers are shared between images and cached, saving disk and time. A container adds one thin writable layer on top (copy-on-write).

Naming, tagging, versioning

registry/namespace/repo:tag
docker.io/myuser/myapp:1.2.0
docker tag myapp:latest myuser/myapp:1.2.0   # add a tag
# avoid relying on :latest in production, pin versions (nginx:1.27-alpine)

Build, pull, push

docker build -t myapp:1.0 .
docker pull ubuntu:24.04
docker login && docker push myuser/myapp:1.0

History and inspect

docker history myapp:1.0       # layers and sizes
docker image inspect myapp:1.0 # metadata, env, cmd, layers

Build cache, optimization, cleanup

  • Put rarely-changing steps (install deps) before frequently-changing ones (copy source).
  • Use small bases (alpine, slim), multi-stage builds, combine RUN commands.
docker image prune -a      # remove unused images
docker builder prune       # clear build cache
docker system prune -a --volumes   # clean everything unused (careful!)
docker system df           # disk usage

4. Dockerfile

Structure and instructions

# Dockerfile for a Node.js app
FROM node:20-alpine            # base image
ARG APP_VER=1.0                # build-time variable
ENV NODE_ENV=production        # runtime variable
WORKDIR /app                   # working dir (created if missing)
COPY package*.json ./          # copy deps first (cache friendly)
RUN npm ci --omit=dev          # run at build time
COPY . .                       # copy source (ADD also extracts tar/URLs)
EXPOSE 3000                    # documents the port
VOLUME /app/data               # mount point for data
USER node                      # run as non-root
HEALTHCHECK --interval=30s CMD wget -qO- http://localhost:3000/health || exit 1
ENTRYPOINT ["node"]
CMD ["server.js"]

.dockerignore

node_modules
.git
*.log
.env

CMD vs ENTRYPOINT

  • ENTRYPOINT: fixed executable, hard to override (needs --entrypoint).
  • CMD: default arguments, easily replaced by docker run image args.
  • Together: docker run myapp other.js runs node other.js.

ARG vs ENV

  • ARG: only during build (--build-arg APP_VER=2.0), gone at runtime.
  • ENV: persists in image and running container (-e overrides).

Multi-stage builds

FROM golang:1.22 AS build
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 go build -o app

FROM alpine:3.20
COPY --from=build /src/app /usr/local/bin/app
USER 1000
CMD ["app"]          # final image ~10 MB, no compiler
Best practices: one process per container, pin versions, non-root user, minimal base, no secrets in layers, order instructions by change frequency.

5. Container Management

Lifecycle

created → running → paused → stopped (exited) → removed. Commands: create, start, pause, unpause, stop, kill, rm.

Foreground, detached, interactive, ports, env, names

docker run nginx                         # foreground, attached to terminal
docker run -d --name web nginx           # detached (background)
docker run -it ubuntu bash               # interactive TTY
docker run -d -p 8080:80 nginx           # host 8080 -> container 80
docker run -d -P nginx                   # publish all EXPOSEd to random ports
docker run -e MYSQL_ROOT_PASSWORD=pass --name db -d mysql:8

Resource limits and restart policies

docker run -d --memory=512m --cpus=1.5 --name app myapp
docker update --memory=1g app
docker run -d --restart=unless-stopped nginx
# policies: no | on-failure[:N] | always | unless-stopped

Logs and troubleshooting

docker logs --tail 50 -f -t web
docker inspect web | grep -i -A3 State
docker exec -it web sh
docker cp web:/etc/nginx/nginx.conf .
docker top web ; docker diff web
Container exits immediately? Check docker logs and exit code (docker inspect -f '{{.State.ExitCode}}'). 137 = killed/OOM, 1 = app error.

6. Storage and Volumes

Container filesystem and writable layer

Data written inside a container lives in its writable layer and is lost when the container is removed. Use volumes or bind mounts for persistent data.

Named, anonymous, bind, tmpfs

docker volume create dbdata
docker run -d -v dbdata:/var/lib/mysql mysql:8          # named volume
docker run -d -v /var/lib/mysql mysql:8                 # anonymous volume
docker run -d -v $(pwd)/site:/usr/share/nginx/html:ro -p 80:80 nginx   # bind mount
docker run -d --tmpfs /tmp:rw,size=64m myapp            # RAM-only, not persisted
docker run --mount type=volume,src=dbdata,dst=/data alpine   # modern syntax
TypeManaged byUse case
Named volumeDockerDatabases, production data
Bind mountHost pathDev, config files
tmpfsRAMTemp or sensitive data

Inspection and management

docker volume ls ; docker volume inspect dbdata
docker volume rm dbdata ; docker volume prune

Backup and restore

# backup
docker run --rm -v dbdata:/data -v $(pwd):/backup alpine tar czf /backup/dbdata.tgz -C /data .
# restore into a new volume
docker volume create dbdata2
docker run --rm -v dbdata2:/data -v $(pwd):/backup alpine tar xzf /backup/dbdata.tgz -C /data

7. Docker Networking

Fundamentals and network drivers

  • bridge (default): private network on the host, NAT to outside; containers reach each other by IP.
  • host: shares host network stack, no isolation, no port mapping needed.
  • none: no networking (loopback only).
  • overlay: multi-host networking for Swarm.
  • macvlan: gives the container its own MAC/IP on the physical LAN.
docker network ls
docker run -d --network host nginx
docker run --network none alpine ip a
docker network create -d macvlan --subnet=192.168.1.0/24 --gateway=192.168.1.1 -o parent=eth0 lan
docker network create -d overlay --attachable ovnet   # needs Swarm

Custom bridge, DNS, container-to-container

On a user-defined bridge, containers resolve each other by name (built-in DNS). The default bridge does not.

docker network create appnet
docker run -d --name db --network appnet -e MYSQL_ROOT_PASSWORD=pw mysql:8
docker run -it --rm --network appnet alpine ping db     # works by name
docker network connect appnet web ; docker network disconnect appnet web
docker network inspect appnet

Port publishing and troubleshooting

docker run -p 127.0.0.1:8080:80 nginx   # bind to localhost only
docker port web
ss -tulpn | grep 8080                   # is the port in use?
docker exec web curl -s db:3306         # test connectivity
sudo iptables -t nat -L -n              # inspect NAT rules
Cannot reach container? Check: right port mapping, app listening on 0.0.0.0 (not 127.0.0.1), same network, firewall (ufw) rules.

8. Docker Compose

Compose defines and runs multi-container apps from one YAML file (compose.yaml). It is built into Docker as docker compose (plugin; install with sudo apt install docker-compose-plugin). YAML basics: indentation with spaces (no tabs), key: value, lists with -.

services:
  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: rootpw
      MYSQL_DATABASE: wp
    volumes: [dbdata:/var/lib/mysql]
    networks: [back]
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      retries: 5
  wordpress:
    image: wordpress:latest
    ports: ["8080:80"]
    environment:
      WORDPRESS_DB_HOST: db
      WORDPRESS_DB_USER: root
      WORDPRESS_DB_PASSWORD: rootpw
      WORDPRESS_DB_NAME: wp
    depends_on:
      db: {condition: service_healthy}   # waits until db is healthy
    networks: [back]
volumes:
  dbdata:
networks:
  back:

Commands

docker compose up -d          # create and start
docker compose ps ; docker compose logs -f wordpress
docker compose exec db bash
docker compose build ; docker compose pull
docker compose config         # validate and view merged file
docker compose down -v        # stop, remove (and volumes with -v)
Troubleshooting: run docker compose config for YAML errors, logs for crashes, check service names used as hostnames, use .env file for variables (${DB_PASS}). Note: depends_on alone only controls start order, not readiness, so pair it with a health check.

9. Docker Hub and Registries

docker login                         # account login (use access tokens)
docker logout
docker tag myapp:1.0 myuser/myapp:1.0
docker push myuser/myapp:1.0
docker pull myuser/myapp:1.0
# Private registry (self-hosted)
docker run -d -p 5000:5000 --name registry registry:2
docker tag myapp localhost:5000/myapp:1.0
docker push localhost:5000/myapp:1.0
  • Repositories: public (free, anyone can pull) or private (login required).
  • Version management: use semantic tags (1.0.0, 1.0, latest) and immutable tags like git SHA (myapp:a1b2c3d).
  • Other registries: GitHub Container Registry, AWS ECR, Harbor, GitLab Registry. Non-HTTPS registries need insecure-registries in /etc/docker/daemon.json.

10. Docker Security

Root vs non-root

RUN adduser -D appuser
USER appuser
docker run --user 1000:1000 myapp

Capabilities, privileged, read-only, secrets

docker run --cap-drop ALL --cap-add NET_BIND_SERVICE nginx
docker run --privileged ...             # AVOID: nearly full host access
docker run --read-only --tmpfs /tmp myapp
docker run --security-opt no-new-privileges myapp
# Secrets (Swarm / Compose): file mounted at /run/secrets/db_pass
printf 'S3cret' | docker secret create db_pass -

Docker socket security

Mounting /var/run/docker.sock into a container gives it root-equivalent control of the host. Avoid it, or use a socket proxy; never expose the TCP daemon port 2375 without TLS.

Vulnerability scanning

docker scout cves myapp:1.0      # Docker Scout
trivy image myapp:1.0            # Trivy (open source)

Resource restrictions, Seccomp, AppArmor

docker run --memory=256m --cpus=0.5 --pids-limit=100 myapp
docker run --security-opt seccomp=profile.json myapp   # restrict syscalls
docker run --security-opt apparmor=docker-default myapp
Best practices: trusted minimal images, pin versions, scan in CI, non-root, read-only FS, drop capabilities, no secrets in ENV or image layers, keep Docker and host patched.

BuildKit, buildx, cache

DOCKER_BUILDKIT=1 docker build -t app .
docker buildx create --use
docker buildx build --platform linux/amd64,linux/arm64 -t myuser/app:1 --push .
# cache mount speeds up package installs
RUN --mount=type=cache,target=/root/.cache/pip pip install -r requirements.txt

Health checks and resource management

docker run -d --health-cmd="curl -f http://localhost || exit 1" --health-interval=30s nginx
docker ps      # shows (healthy) / (unhealthy)

Docker Swarm: services, replicas, cluster

docker swarm init --advertise-addr 192.168.1.10
docker swarm join --token SWMTKN-xxx 192.168.1.10:2377   # on workers
docker node ls
docker service create --name web --replicas 3 -p 80:80 nginx:1.26
docker service ls ; docker service ps web
docker service scale web=5

Rolling updates and rollback

docker service update --image nginx:1.27 --update-parallelism 1 --update-delay 10s web
docker service rollback web

Events, plugins, advanced troubleshooting

docker events --filter type=container
docker plugin ls ; docker plugin install grafana/loki-docker-driver
journalctl -u docker -e              # daemon logs
docker system df ; docker stats --no-stream
sudo dockerd --debug                 # debug mode

12. Monitoring and Logging

Built-in tools

docker logs -f --since 10m web
docker stats ; docker events

Logging drivers

# /etc/docker/daemon.json  (restart docker after)
{ "log-driver": "json-file", "log-opts": {"max-size": "10m", "max-file": "3"} }
docker run --log-driver syslog --log-opt syslog-address=udp://10.0.0.5:514 nginx

cAdvisor + Prometheus + Grafana

services:
  cadvisor:
    image: gcr.io/cadvisor/cadvisor
    volumes: ["/:/rootfs:ro","/var/run:/var/run:ro","/sys:/sys:ro","/var/lib/docker/:/var/lib/docker:ro"]
    ports: ["8081:8080"]
  prometheus:
    image: prom/prometheus
    volumes: ["./prometheus.yml:/etc/prometheus/prometheus.yml"]
    ports: ["9090:9090"]
  grafana:
    image: grafana/grafana
    ports: ["3000:3000"]

# prometheus.yml
scrape_configs:
  - job_name: cadvisor
    static_configs: [{targets: ["cadvisor:8080"]}]

In Grafana add Prometheus (http://prometheus:9090) as data source, import dashboard ID 193 or 14282 for container metrics, and set alert rules (e.g. CPU above 80% for 5 minutes).

13. Docker with DevOps Tools

Git and GitHub

git clone https://github.com/user/app.git && cd app
docker build -t app . ; git push   # GitHub Actions can build and push images

Jenkins and CI/CD

pipeline {
  agent any
  stages {
    stage('Checkout'){ steps { git 'https://github.com/user/app.git' } }
    stage('Build'){ steps { sh 'docker build -t myuser/app:${BUILD_NUMBER} .' } }
    stage('Push'){ steps { withCredentials([usernamePassword(credentialsId:'dh',usernameVariable:'U',passwordVariable:'P')]){
        sh 'echo $P | docker login -u $U --password-stdin && docker push myuser/app:${BUILD_NUMBER}' } } }
    stage('Deploy'){ steps { sh 'docker compose up -d' } }
  }
}

Ansible and Terraform

# Ansible
- hosts: web
  tasks:
    - community.docker.docker_container:
        name: web
        image: nginx
        ports: ["80:80"]
# Terraform (kreuzwerker/docker provider)
resource "docker_image" "nginx" { name = "nginx:latest" }
resource "docker_container" "web" {
  name  = "web"
  image = docker_image.nginx.image_id
  ports { internal = 80  external = 8080 }
}

Docker on AWS EC2

sudo apt update && sudo apt install -y docker.io    # on Ubuntu EC2

Kubernetes

Docker builds images; Kubernetes orchestrates them at scale (self-healing, autoscaling, rolling updates).

kubectl create deployment web --image=myuser/app:1.0 --replicas=3

Nginx (reverse proxy) and Prometheus/Grafana

docker run -d -p 80:80 -v $(pwd)/nginx.conf:/etc/nginx/conf.d/default.conf:ro --network appnet nginx
