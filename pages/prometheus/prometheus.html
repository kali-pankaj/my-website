01 — Overview

What Prometheus actually is

Prometheus is a monitoring system and time-series database, originally built at SoundCloud and released in 2012. Instead of waiting for applications to push metrics to it, it pulls (scrapes) them on a schedule from HTTP endpoints exposed by the services being monitored. It's now a graduated project of the Cloud Native Computing Foundation and the de facto metrics standard in the Kubernetes ecosystem. It doesn't render dashboards itself — that's usually where Grafana comes in.

CONCEPT

Scraping

Prometheus pulls metrics over HTTP from targets at a configured interval, typically every 15–60s.

CONCEPT

Time series

Each metric is identified by a name plus a set of key/value labels — that's what makes it queryable by dimension.

CONCEPT

Exporters

Small processes that translate a system's native stats (Postgres, Nginx, hardware) into Prometheus format.

CONCEPT

PromQL

The query language used to select, aggregate, and do math over time series — both ad hoc and in rules.

CONCEPT

Alertmanager

A separate component that receives firing alerts and handles grouping, silencing, and routing them.

CONCEPT

Service discovery

Automatic detection of scrape targets from Kubernetes, Consul, EC2, and other dynamic environments.

02 — Architecture

How the pieces fit together

Prometheus scrapes targets directly, stores results in its own local time-series database, evaluates rules against that data, and hands off anything alert-worthy to Alertmanager. Grafana or the built-in expression browser sit on top to visualize it.

Targets App /exporters /node
→

→

Prometheus server also feeds Grafana and the built-in expression browser directly for queries

04 — Query language

PromQL, a quick taste

A few representative queries — enough to recognize the shape of PromQL, not a full reference.

up == 0 Every target that Prometheus currently considers down.
rate(http_requests_total[5m]) Per-second average request rate over the last 5 minutes.
sum by (job) (rate(http_requests_total[5m])) The same rate, aggregated per job label.
histogram_quantile(0.95, rate(request_duration_bucket[5m])) 95th-percentile latency computed from a histogram metric.
05 — Getting started

Installing Prometheus

Pick a path. Binaries and checksums always come from the official download page linked below.

# runs Prometheus with the sample config, exposed on port 9090 docker run -p 9090:9090 prom/prometheus

For anything beyond a quick test, mount a named volume and your own prometheus.yml.

# download + extract the precompiled binary from the official page wget https://github.com/prometheus/prometheus/releases/download/v<version>/prometheus-<version>.linux-amd64.tar.gz tar xvf prometheus-<version>.linux-amd64.tar.gz cd prometheus-<version>.linux-amd64 ./prometheus --config.file=prometheus.yml

Distro packages exist too, but the official docs recommend the precompiled binary for the latest release.

# via Homebrew brew update brew install prometheus brew services start prometheus

Homebrew installs the same binary you'd get from the download page, just with service management built in.

# download the .zip for windows-amd64 from the official page, then: cd prometheus-<version>.windows-amd64 .\prometheus.exe --config.file=prometheus.yml

No installer — it's a single executable plus a config file, same as on Linux and macOS.

→ After starting, Prometheus's own expression browser is at http://localhost:9090.
