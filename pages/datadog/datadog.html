01 — Overview

What Datadog actually is

Datadog is a fully managed monitoring and security platform, founded in 2010, that unifies infrastructure metrics, application traces, logs, and real-user data under one product with 1,000+ built-in integrations. Unlike Prometheus or Grafana, you don't self-host any of it — a lightweight Agent runs on your hosts and pushes data to Datadog's cloud, where you build dashboards, monitors, and alerts through the web app.

CONCEPT

Agent

Open-source software installed on each host that collects and forwards metrics, logs, and traces to Datadog.

CONCEPT

Integrations

Pre-built connectors — over a thousand — that plug the Agent into things like Postgres, Kubernetes, or AWS.

CONCEPT

Tags

Key:value labels attached to hosts and metrics, used to slice, filter, and group everything in the UI.

CONCEPT

Monitors

Datadog's term for alert rules — they evaluate metrics, logs, or checks and notify when thresholds trip.

CONCEPT

APM / Traces

Distributed tracing that follows a request across services, correlated with logs and infrastructure metrics.

CONCEPT

Dashboards

Drag-and-drop widgets over any metric, log, or trace data — built in the Datadog web app, not self-hosted.

02 — Architecture

How the pieces fit together

Unlike a pull-based system, the Datadog Agent pushes data outward on its own schedule. Everything downstream — storage, querying, dashboards, alert evaluation — runs on Datadog's infrastructure, not yours.

Your hosts Datadog Agent (+ integrations)
→
Datadog SaaS Ingest · store · evaluate
→

04 — Alerting

How a monitor is put together

A monitor is Datadog's alert primitive — the shape stays the same across metric, log, and APM monitors.

Type What's being evaluated — metric, log, APM trace, process, or a synthetic check.
Query The metric/log query and aggregation, scoped by tags, e.g. host or service.
Threshold Warning and alert levels, plus how long a breach must persist before it fires.
Notification Where it goes — Slack, PagerDuty, email, webhook — using @-mention syntax in the message.
05 — Getting started

Installing the Datadog Agent

Every path needs a Datadog account and an API key first — grab one from the official signup page linked below.

# one-line install script, prompts for your API key DD_API_KEY=<YOUR_API_KEY> DD_SITE="datadoghq.com" \ bash -c "$(curl -L https://install.datadoghq.com/scripts/install_script_agent7.sh)"

DEB/RPM packages are also available directly if you'd rather manage the install yourself.

# runs the Agent as a container, mounting the host's proc & sockets docker run -d --name datadog-agent \ -e DD_API_KEY=<YOUR_API_KEY> \ -e DD_SITE="datadoghq.com" \ -v /var/run/docker.sock:/var/run/docker.sock:ro \ -v /proc/:/host/proc/:ro \ -v /sys/fs/cgroup/:/host/sys/fs/cgroup:ro \ gcr.io/datadoghq/agent:7

A Helm chart is the recommended path for Kubernetes rather than a raw Docker run.

# via the official install script (Homebrew is not the primary path) DD_API_KEY=<YOUR_API_KEY> DD_SITE="datadoghq.com" \ bash -c "$(curl -L https://install.datadoghq.com/scripts/install_mac_os.sh)"

The Agent Manager GUI is available locally afterward for checking status and configuration.

# download the MSI installer from the official docs, then run it and: 1. Open datadog-agent-7-latest.amd64.msi 2. Accept the license agreement 3. Enter your Datadog API key when prompted

Runs under a dedicated ddagentuser account created during setup.

→ The Agent itself is open source — source at github.com/DataDog/datadog-agent — but it only reports into the hosted Datadog platform.
